# Sample order flow for the replay driver.
#   N <id> <BUY|SELL> <LIMIT|MARKET> <GTC|IOC> <price> <qty>
#   C <id>

# Build a two-sided book.
N 1 BUY  LIMIT GTC 100 10
N 2 BUY  LIMIT GTC 100  5
N 3 BUY  LIMIT GTC  99 20
N 4 SELL LIMIT GTC 102  8
N 5 SELL LIMIT GTC 103 15

# Cross the spread partially: takes both bids at 100 in arrival order.
N 6 SELL LIMIT GTC 100 12

# Cancel the residual of order 2, then try again to see the reject.
C 2
C 2

# Sweep the ask side with a market order that outsizes it.
N 7 BUY MARKET IOC 0 30

# An immediate-or-cancel order that crosses nothing.
N 8 SELL LIMIT IOC 150 5

# Rebuild and cross exactly.
N 9  BUY  LIMIT GTC 99 20
N 10 SELL LIMIT GTC 99 40

# Price improvement: a buyer willing to pay 110 meets a seller asking
# 105, and the trade must print at 105. The aggressor accepted the
# resting order's terms, so the improvement is theirs.
#
# Added because the earlier file happened to cross every order at an
# identical price, so it could not have detected the execution price
# rule changing at all. A canary that cannot see a whole class of change
# is a weak canary.
N 11 SELL LIMIT GTC 105 10
N 12 BUY  LIMIT GTC 110 10

# Time priority across two resting orders at one price, so a change to
# the FIFO rule also moves these checksums.
N 13 BUY LIMIT GTC 100 5
N 14 BUY LIMIT GTC 100 5
N 15 SELL LIMIT GTC 100 5
